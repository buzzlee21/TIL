# 푸시 전 보안 체크리스트

`git push` 전에 매번 위에서부터 확인한다.
한 번 푸시하면 GitHub에 남고, 지워도 **히스토리(과거 기록)**에 남을 수 있다.

## 1. 올라갈 내용 확인

- [ ] `git status` 로 의도하지 않은 파일이 없는지 본다
- [ ] `git log origin/master..HEAD --stat` 로 이번에 올라갈 커밋과 파일을 본다
- [ ] `git diff origin/master --stat` 로 바뀌는 파일 목록을 본다

## 2. 비밀정보가 들어있지 않은가

아래는 **절대 올리면 안 되는 것**이다.

- [ ] 비밀번호, 토큰, API 키 (예: `ghp_...`, `sk-...`, `AKIA...`)
- [ ] `.env` 파일, `*.pem`, `*.key`, `id_rsa` 같은 키 파일
- [ ] 개인정보 (전화번호, 주소, 주민번호, 계좌번호)
- [ ] 회사/학원 내부 자료, 저작권이 있는 강의 자료 원본
- [ ] 코드나 메모에 직접 적어둔 접속 주소 (DB 주소, 서버 IP)

검색 명령어 (아무것도 안 나오면 통과):

```bash
git grep -nIiE "password|passwd|secret|token|api[_-]?key|private[_-]?key|BEGIN [A-Z ]*PRIVATE|AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{20,}|sk-[A-Za-z0-9]{20,}"
```

- [ ] 위 검색 결과가 없거나, 나온 것이 진짜 비밀이 아님을 확인했다
- [ ] 이번에 올라갈 커밋의 변경 내용도 확인했다: `git log -p origin/master..HEAD`

## 3. 파일이 제외되고 있는가

- [ ] `.gitignore` 에 `.env`, `*.key`, `*.pem`, `__pycache__/`, `.venv/` 등이 들어 있다
- [ ] `git ls-files` 로 추적 중인 파일 목록에 민감한 파일이 없다

## 4. 저장소와 계정이 맞는가

- [ ] `git remote -v` 로 올라갈 주소가 내 의도와 같다
- [ ] `git branch -vv` 로 올라갈 브랜치가 맞다
- [ ] 공개(public) 저장소라면 **전 세계 누구나 볼 수 있다**는 것을 알고 있다

## 5. 커밋 작성자 정보

- [ ] `git log --format='%an <%ae>' | sort -u` 로 커밋에 남은 이름/이메일을 확인했다
- [ ] 이메일을 공개하기 싫다면 GitHub의 noreply 주소를 쓴다
  (GitHub 설정 > Emails > "Keep my email addresses private")

## 6. 실수했다면

| 상황 | 대처 |
|---|---|
| 커밋은 했지만 **아직 푸시 전** | `git reset --soft HEAD~1` 로 커밋만 취소하고 파일을 고친 뒤 다시 커밋 |
| 비밀정보를 **이미 푸시함** | 파일을 지우는 것으로 끝나지 않는다. **먼저 그 키/비밀번호를 폐기하고 새로 발급**한 뒤 히스토리 정리를 한다 |

> 푸시된 비밀정보는 이미 유출된 것으로 보고, 폐기(재발급)가 1순위다.

## 푸시 직전 최종 확인

- [ ] 1~5번을 모두 확인했다
- [ ] `git push` 실행
